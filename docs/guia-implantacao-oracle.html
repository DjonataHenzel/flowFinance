1. Visão geral e custos

O FlowFinance será executado em uma VM Linux na Oracle Cloud. O PostgreSQL, o backend Spring Boot, o frontend e o proxy HTTPS serão containers independentes, conectados por uma rede Docker privada.

Internet
   │
   ▼
https://flowfinance.duckdns.org
   │ portas públicas 80/443
   ▼
Caddy (HTTPS + frontend)
   │ /api/*
   ▼
Backend Spring Boot ─── PostgreSQL
   │
   └── agendador de notificações ─── ntfy.sh
ComponenteFunçãoExposição pública
CaddyHTTPS, frontend e encaminhamento de /apiPortas 80 e 443
BackendAPI e agendadores SpringSomente rede Docker
PostgreSQLDados persistentesSomente rede Docker

Dentro dos limites Always Free, VM, disco, Docker, PostgreSQL, DuckDNS e certificado TLS podem custar R$ 0. O cadastro da Oracle geralmente exige cartão para verificação. Não faça upgrade para uma conta paga e não crie recursos sem o selo Always Free Eligible.

Limitação importante: ofertas gratuitas, limites e telas podem mudar. Sempre confira a estimativa apresentada pela Oracle antes de confirmar um recurso.

2. Preparação e segurança

2.1 Informações que serão necessárias

  • E-mail e telefone para a conta Oracle.
  • Cartão aceito pela Oracle para verificação de identidade.
  • Conta Google, GitHub ou outra aceita pelo DuckDNS.
  • Repositório Git do FlowFinance acessível pela VM.
  • Uma senha inédita e forte para o PostgreSQL.
  • Uma nova senha administrativa do FlowFinance.

2.2 Segredos que nunca devem ser compartilhados

  • Chave SSH privada.
  • Token do DuckDNS.
  • Senha do PostgreSQL.
  • Token de acesso do GitHub.
  • Conteúdo do arquivo .env de produção.
Nunca salve esses dados no Git, em capturas de tela públicas, mensagens ou arquivos anexados a chamados.

3. Criação da conta Oracle Cloud

  1. Acesse oracle.com/cloud/free e escolha a criação de conta gratuita.
  2. Informe nome, país, e-mail e telefone verdadeiros.
  3. Confirme o e-mail e conclua a verificação solicitada.
  4. Escolha cuidadosamente a Home Region. Para menor latência, prefira Brazil East (São Paulo), se os recursos gratuitos estiverem disponíveis.
  5. Cadastre o método de pagamento apenas para verificação.
  6. Após entrar, confirme que a conta aparece como Free Tier e não clique em Upgrade to Pay As You Go.
A Home Region é uma decisão importante. Recursos Always Free são criados na região principal da conta e a capacidade Ampere pode estar temporariamente indisponível.

4. Criação da chave SSH no Windows

Abra o PowerShell e execute:

New-Item -ItemType Directory -Force "$env:USERPROFILE\.ssh"
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\flowfinance_oracle" -C "flowfinance-oracle"

Serão criados:

C:\Users\SEU_USUARIO\.ssh\flowfinance_oracle      # privada
C:\Users\SEU_USUARIO\.ssh\flowfinance_oracle.pub  # pública

Exiba e copie a chave pública:

Get-Content "$env:USERPROFILE\.ssh\flowfinance_oracle.pub"
A chave sem a extensão .pub é privada. Não a envie à Oracle, não a copie para a VM e não a adicione ao repositório.

5. Criação da VM Ampere Always Free

  1. No Console OCI, abra Compute → Instances → Create instance.
  2. Nomeie a instância como flowfinance-prod.
  3. Em imagem, selecione Canonical Ubuntu 24.04 LTS compatível com ARM64/aarch64.
  4. Em shape, selecione VM.Standard.A1.Flex.
  5. Configure 2 OCPUs e 12 GB de RAM, respeitando o total Always Free mostrado no seu painel.
  6. Em rede, crie uma VCN e uma subnet pública; marque a atribuição de IPv4 público.
  7. Em SSH, escolha Paste public keys e cole a chave terminada em .pub.
  8. Use um boot volume próximo de 50 GB, sem opções adicionais pagas.
  9. Confirme o selo Always Free Eligible e a estimativa antes de clicar em Create.

Nomeflowfinance-prod

Aguarde o estado Running e anote o IPv4 público em local privado.

6. Rede, IP e portas

6.1 Regras de entrada na Oracle

Na instância, abra a subnet associada, a Security List padrão e adicione regras stateful:

OrigemProtocoloDestinoUso
0.0.0.0/0TCP80HTTP e emissão inicial do certificado
0.0.0.0/0TCP443HTTPS
SEU_IP/32TCP22Administração SSH

Não libere publicamente 5432, 8080 ou 5173.

6.2 Teste de SSH

ssh -i "$env:USERPROFILE\.ssh\flowfinance_oracle" ubuntu@IP_PUBLICO

Na primeira conexão, confira o IP e aceite a impressão digital. Na VM, execute:

uname -m
cat /etc/os-release
free -h
df -h

O resultado de uname -m deve ser aarch64.

6.3 IP reservado

É recomendável substituir o IP efêmero por um IP público reservado no gerenciamento de IPs da OCI. Um IP reservado permanece como recurso regional e pode ser reassociado a outra VM. Siga o assistente do Console sem excluir o IP atual antes de confirmar que o novo endereço foi associado corretamente.

7. Configuração do DuckDNS

  1. Acesse duckdns.org e autentique-se.
  2. No campo de domínio, informe flowfinance.
  3. Crie o subdomínio. Se indisponível, escolha uma variação e atualize este guia/configuração.
  4. No campo Current IP, informe o IPv4 público da VM e clique em Update IP.
  5. Guarde o token do DuckDNS como segredo.

No Windows, valide:

Resolve-DnsName flowfinance.duckdns.org

O registro A deve retornar o IP da VM. A propagação normalmente é rápida, mas caches DNS podem atrasar a atualização.

8. Preparação do Ubuntu e instalação do Docker

Conecte-se por SSH e atualize o sistema:

sudo apt update
sudo apt upgrade -y
sudo apt install -y ca-certificates curl git

8.1 Instalação oficial do Docker

sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

echo "Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc" | sudo tee /etc/apt/sources.list.d/docker.sources > /dev/null

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Habilite e teste:

sudo systemctl enable --now docker
sudo docker run --rm hello-world
sudo docker compose version

Permita o uso pelo usuário ubuntu:

sudo usermod -aG docker ubuntu
exit

Conecte-se novamente por SSH e valide:

docker version
docker compose version

9. Preparação do projeto para produção

Antes da publicação, o repositório deve possuir imagens ARM64 e uma composição de produção. A estrutura esperada é:

FlowFinance/
├── compose.yaml
├── .env.example
├── backend/
│   ├── Dockerfile
│   └── .dockerignore
├── frontend/
│   ├── Dockerfile
│   ├── Caddyfile
│   └── .dockerignore
└── deploy/
    ├── backup-postgres.sh
    └── restore-postgres.sh

9.1 Variáveis de produção

O arquivo real .env existirá somente na VM. Exemplo sem valores secretos:

POSTGRES_DB=flowfinance
POSTGRES_USER=flowfinance
POSTGRES_PASSWORD=SUBSTITUA_POR_SENHA_FORTE
SESSION_COOKIE_SECURE=true
NTFY_BASE_URL=https://ntfy.sh
FLOWFINANCE_HOST=flowfinance.duckdns.org
TZ=America/Sao_Paulo
APP_TIME_ZONE=America/Sao_Paulo

Gere uma senha no PowerShell local:

-join ((33..126) | Get-Random -Count 32 | ForEach-Object {[char]$_})
Alguns caracteres especiais exigem escape em arquivos dotenv. Uma alternativa segura é usar uma senha longa composta por letras, números, hífen e sublinhado.

9.2 Regras indispensáveis

  • O backend deve receber DB_URL=jdbc:postgresql://postgres:5432/flowfinance.
  • O PostgreSQL deve usar volume nomeado.
  • Backend e PostgreSQL não devem declarar portas públicas.
  • Os serviços devem usar restart: unless-stopped.
  • O Caddy deve encaminhar /api/* ao backend e servir o frontend.
  • A imagem Java e a imagem PostgreSQL devem oferecer ARM64.

10. Publicação do FlowFinance

10.1 Clonar o repositório

cd /opt
sudo mkdir -p flowfinance
sudo chown ubuntu:ubuntu flowfinance
git clone URL_DO_REPOSITORIO /opt/flowfinance
cd /opt/flowfinance

Para repositório privado, prefira uma deploy key somente leitura. Não coloque senha ou token diretamente na URL gravada no histórico do shell.

10.2 Criar o arquivo de ambiente

cp .env.example .env
nano .env

Depois de preencher, proteja:

chmod 600 .env

10.3 Construir e iniciar

docker compose config
docker compose build --pull
docker compose up -d
docker compose ps

Acompanhe os logs:

docker compose logs -f --tail=200

Procure no backend mensagens equivalentes a:

Successfully validated ... migrations
Tomcat started
Started FlowFinanceApplication

Pressione Ctrl+C para sair dos logs; isso não encerra os containers.

11. HTTPS e acesso pela URL

Para emitir o certificado automaticamente, as seguintes condições devem ser verdadeiras:

  • flowfinance.duckdns.org aponta ao IP público correto.
  • Portas 80 e 443 estão abertas na OCI.
  • Nenhum outro processo ocupa essas portas.
  • Caddy está em execução.

Um Caddyfile típico:

flowfinance.duckdns.org {
    encode zstd gzip

    handle /api/* {
        reverse_proxy backend:8080
    }

    handle {
        root * /srv
        try_files {path} /index.html
        file_server
    }
}

Caddy obtém e renova o certificado automaticamente. Valide no navegador:

https://flowfinance.duckdns.org

No Windows, testes adicionais:

curl.exe -I http://flowfinance.duckdns.org
curl.exe -I https://flowfinance.duckdns.org

HTTP deve redirecionar para HTTPS. O navegador deve exibir certificado válido.

11.1 Configurações obrigatórias do FlowFinance

  • SESSION_COOKIE_SECURE=true.
  • APP_TIME_ZONE e TZ devem usar o mesmo fuso, normalmente America/Sao_Paulo.
  • CORS restrito a https://flowfinance.duckdns.org.
  • Senha padrão do banco removida em produção.
  • Senha admin/admin alterada imediatamente.

12. Backups e restauração

O volume protege contra recriação de containers, mas não substitui backup. Uma falha da VM ou exclusão do volume pode apagar os dados.

12.1 Backup manual

mkdir -p /opt/flowfinance-backups
cd /opt/flowfinance
docker compose exec -T postgres pg_dump -U flowfinance -d flowfinance -Fc \
  > /opt/flowfinance-backups/flowfinance-$(date +%Y%m%d-%H%M%S).dump

12.2 Verificação

ls -lh /opt/flowfinance-backups
file /opt/flowfinance-backups/*.dump

12.3 Restauração

A restauração substitui dados. Faça um backup adicional e confirme o arquivo antes de executar.
cat ARQUIVO.dump | docker compose exec -T postgres \
  pg_restore -U flowfinance -d flowfinance --clean --if-exists

Automatize um backup diário por cron, retenha versões por período limitado e copie pelo menos uma versão para fora da VM. Teste a restauração periodicamente.

13. Atualização, monitoramento e operação

13.1 Atualizar aplicação

cd /opt/flowfinance
git pull --ff-only
docker compose build --pull
docker compose up -d
docker image prune -f
docker compose ps

Faça backup antes de atualizações com migrations.

13.2 Comandos úteis

docker compose ps
docker compose logs --tail=200 backend
docker compose logs --tail=200 caddy
docker compose logs --tail=200 postgres
docker stats
df -h
free -h

13.3 Reinicialização automática

sudo systemctl is-enabled docker
sudo reboot

Após alguns minutos, reconecte-se e confirme:

cd /opt/flowfinance
docker compose ps

13.4 Teste da operação 24 horas

  1. Cadastre um tópico ntfy de teste.
  2. Crie um compromisso para alguns minutos no futuro.
  3. Feche o navegador e desligue o computador local.
  4. Confirme o recebimento no celular.
  5. Confira o histórico e os logs ao retornar.

14.1 Fuso horário

Confirme na VM e nos containers:

timedatectl
docker compose exec backend date
docker compose exec postgres date

O projeto deve utilizar America/Sao_Paulo de forma consistente para que o scheduler execute no horário esperado.

15. Checklist final

  • Conta Oracle permanece no Free Tier.
  • VM possui selo Always Free Eligible.
  • Arquitetura é aarch64.
  • SSH usa chave e está restrito.
  • Somente 80/443 estão públicos para a aplicação.
  • DuckDNS aponta ao IP reservado correto.
  • HTTPS apresenta certificado válido.
  • PostgreSQL não está exposto.
  • .env não está no Git e possui permissão 600.
  • Senha administrativa padrão foi alterada.
  • CORS aceita apenas a URL de produção.
  • Containers reiniciam automaticamente.
  • Backup diário está ativo e uma cópia sai da VM.
  • Restauração foi testada.
  • Notificação foi recebida com o computador local desligado.
